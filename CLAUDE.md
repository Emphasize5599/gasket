## Layout
- `src/com/bensanzone/fuelmap/MainActivity.java`: the only Java class. It hosts a WebView and exposes the `Native` JS bridge, plus `GasketSite` for the hidden site WebViews.
- `assets/web/`: the whole UI, in plain HTML/CSS/JS with no framework or bundler. `trip.js` is pure logic and also runs in Node. `app.js` contains a browser stand-in for `Native`, so the UI runs in desktop Chrome.
- `assets/*_worker.js`: scripts injected into hidden walmart.com, murphyusa.com and Google Maps pages. `nhtsa_worker.js` reads NHTSA's recall page for a VIN: in the background (`Native.siteRead`, automatic, at most weekly) or shown to the user (`Native.siteShow`, the button). If the page shows a check (CAPTCHA, Access Denied) the read reports `blocked` and stops; nothing ever gets past a check.
- Garage → Tires (`tires.js`, `TireMath` is pure and tested in Node): factory size and the tires in that size come from Tire Rack via `tirerack_worker.js` (`Native.siteRead`, cached; blocked = type it in). Tire Rack's size page only answers to its own names (model + clarifier, e.g. `Sienna FWD` + `LE V6`), so: step `models` asks the service behind its vehicle menus (`/survey/ValidationServlet?autoYear&autoMake&newDesktop=true`, XML `<models>`) once per year/make/model (`tires.tr`, `verKey` v3, 60 days), `TireMath.rankModels` keeps the models that are this car and `modelsToAsk` the likely ones, step `clars` asks their versions (`&autoModel=`, XML `<clarifiers>`; two per read, 0.8 s apart: bursts get "currently unavailable" = blocked, retried after 6 h), `TireMath.pickVersion` matches by trim words, drive, cylinders and body and auto-picks only when certain (`tires.trVer` `{model, clar, auto, basis}`; an auto match is redone if those details change); otherwise `#tzVerSel` lists the versions (plus other models, `tires.trWant`) and you pick. A model with no clarifiers gets "currently unavailable" from SelectTireSize.jsp, so step `oesize` does what Tire Rack's menu does: `/SetCurrentVehicleServlet?ajax=true&…` (JSON `vehicleZipSet: success`), then `/modalPopups/selectOETireSize.jsp?…`, read only if the panel names this vehicle (it shows the last vehicle set otherwise); TireSearchResults.jsp works for these without `autoModClar`. Fuel API has only 3 colorized angles (001 / 014 / 032); spins and stills are single-color. Tread left = measured, or new depth − (new − 2) × miles ÷ (life × rotation factor); life = mileage warranty, else treadwear × 100, else 50k.
- Garage → Tires is split: "Tire details" (a row opening its own `A.subPage`: size, type → brand → model, wear rating, fuel /10; each hooked-up trailer gets a row and page too, ending in Delete / Unhook / Discard changes (orange); new trailers start hooked up; unhooked ones are under "Saved trailers"), then Tread left (one answer, or every position when `tires.corners.split`: `TireMath.positions` = the corners, a dually's inner rear tires (`corners.dually`; `duallyState`: VIN `info.drw`, hidden for EPA-rated cars and non-trucks), and in tow mode (`tires.towMode`) each hooked-up trailer in `tires.trailers` (keys `<trailerId>:a<axle><side>`). `corners.mode` is `depth` or `miles` (each tire's miles + warranty + rotation, warranty defaulting to its car's/trailer's details; per-tire page via `A.subPage`). `TireMath.missing` lists incomplete tires: the Garage's Next waits for them (or "Discard tire changes", back to the last complete set). Older saves (`extra`, `corners.trailer`) are upgraded), then Spare tire. `TireMath.rotation` puts the better pair on the rear (understeer over oversteer) and never moves a tire at 4/32 or less to the rear (FWD worn fronts = replace); `fuelScore` is rules, nudged ±1 by `Severity.compare`. The spare's kind comes from Brave (`brave_worker.js` with `kind: 'spare'`, `parseSpare`), confirmed by you; Advice asks for "I aired up my spare" every 30 days, and Advisory's Next waits for it (`Tires.spareDue`). The two hidden Brave reads take turns (`Garage.braveSerial`).
- Garage → Climate control (`climate.js`, `ClimateMath` is pure and tested in Node): `car.climate = {caps, presets}`; presets are `season` (one each, picked by month), `weather` ("What would you do if it's…": one per situation in `ClimateMath.WEATHER`, each tagged with the seasons it comes with; reached from "Adjust for special weather conditions" under each season (`openWeather`, a subpage listing `situations(season)`; a situation's page returns to it), one answer shared by every season that has it; Advice shows this time of year's) or `custom`, each on its own `A.subPage` (Delete / Discard changes) and starting from `ClimateMath.starter` (fresh air except smoke). Advice's Cabin climate card shows this season's preset and the fresh-air-over-recirculate advice (when recirculate makes sense: `ClimateMath.recircOk`); "I understand when to use recirculate" is ticked once (`S.recircAck`, `Climate.ackDue`) and Advisory's Next waits for it (tests pre-tick it in `trip_mocks.js`).
- Fuel mode (`S.fuelMode`: `gas` / `ev` / `h2`): the pill `#btnMode` left of the top bar's `#grades` opens `#modeMenu` (`app.js` `setMode`; "EV & hydrogen options…" opens `AltFuel.open`). In ⚡ / H₂ `#grades` is `AltFuel.seg` (charger speed `S.alt.evSpeed` dc / l2 / all; pressure `S.alt.h2Press`), and the list, pins, refresh and "Search this area" go to `altfuel.js` (AFDC). The mode follows the car's kind on `garagechange`. The lookup count `#apiCount` sits under the bar beside `#status` (back in the bar's row during a trip).
- Every `<details>` gets the same chevron on the right (app.css); `A.scrollHint(el)` adds the ↓ / ↑ button to a scrolling area.
- `A.subPage(title, html, onOpen)` opens a submenu page (Back bar, phone Back closes it; onOpen may return a cleanup). Tires' "why" pages loop (`loop()` in tires.js, continuous rain) until the page closes; tests jump to a moment with `el.__anim.at(t)`.
- Storage vs cache: settings (SharedPreferences), the KV namespaces in `MainActivity.KV_STORAGE` (saved trips, Google answers, the model's setup) and `files/ai` (the model) are storage; other KV namespaces live in the cache dir. Rebuildable lookups inside cars (`CAR_CACHE` / `TIRE_CACHE` in app.js, plus `S.recallSev`) are saved apart in KV `lookups` (cache) and merged back at start.
- Recall rating runs in a classic Web Worker made from a blob (a module worker won't start from the `file://` page); it imports transformers.js itself and embeds a few texts per message, so the page never blocks. No worker: it runs in the page, one at a time with pauses. Pauses between groups are longer when Advisory isn't on screen (`Severity.focus`). Open recalls (after the VIN check) are rated first; the folded list only once opened.
- The VIN is private: masked in its box (eye to show), never shown elsewhere, and `log.js` writes `[VIN]` for any VIN.
- Garage → Your car: one car at a time (`carousel` in garage.js: swipe / ‹ › / arrow keys, dots are the `data-car` buttons, Remove is in Edit). Pictures from `carpics.js` (`CarPicMath` pure, tested in Node): photo mode (default) = NHTSA's `vehiclePicture` (api.nhtsa.gov/vehicles/byYmmt), else the best Wikimedia Commons file (`wikiPick`: make + every model word in the file name, year within 3, skips interiors / rear views / parts; credited with photographer, license and a link), else the doodle; doodle mode (`car.picMode = 'doodle'`, Edit → Picture) = `CarPics.drawing`, the app's side view of the body style (`bodyOf`: VIN `info.body`, EPA `epa.vclass`, NHTSA's listing, type) in `car.paint`; with `S.fuelKey` (Settings; scrubbed from logs, never exported; `Native.fetchFuel`, key as Basic auth, never in a URL) Photo mode also lists the trim's factory colors (loaded when Edit opens) and a picked one shows Fuel API's picture (`color_0640_032_png`, else `color_0640_001_png` for older cars that only have the side view (`bestColors`): EVOX's colorized set has only angles 001 / 014 / 032, NHTSA's photo is still shot 046 with no color versions), exactly as delivered (never strip, shrink, crop or cover its watermark: COMPLIANCE.md #9); doodle colors are the app's own palette. `Native.fetchImage` (static.nhtsa.gov, upload.wikimedia.org, i.fuelapi.com) returns a ≤640 px WebP data URL, kept in KV `carpics` (app storage, full backup included); `car.pic = {nhtsa, wiki, fuel}` stays with car settings. Older cached pictures and metadata are migrated on upgrade. Tests mock `__mocks.nhtsaPic` / `commons` / `fuel` / `image`.
- Garage → tank size: a gas / hybrid car with none asks Brave Search's AI answer once (`brave_worker.js`, `Native.siteRead` key `brave`; failed = ↻ in the box, or "Search Brave yourself" = `siteShow`). A check on Brave's page is never got around.
- Garage → About this car: `info.src` / `info.featSrc` record where each detail came from (`vin`, `epa` = confirmed; `user`). Versions of a model come from the EPA options for the year/make/model plus its 2WD/AWD sibling models; cars with no EPA record and no VIN are "custom" and keep the menus.
- Parameters → how much gas: `fuelgauge.js` (`FuelGauge.math` is pure and tested in Node). `S.trip.fuel` = `{mode: gauge | miles | pct, n16 (sixteenths), pct, miles}`; `S.trip.milesLeft` follows it for saved trips and old exports. EVs get percent or miles. Empty (gauge E, 0%, 0 miles; `FuelGauge.math.empty`) isn't an answer: steps 5–7 stay gray and `emptyHelp` (tripui) shows a red box with the fuel to reach the nearest known station (straight line × 1.25) or the first one along the route, +0.1 mi (`math.toReach`), from `knownStations()` (the map's plus this route's saved Google answers; no lookups).
- Route: routes are fetched by themselves (`autoRoute`) whenever the Route step has a link or both addresses and no routes; changing avoid / round trip brings the Get routes button back until the link or addresses change. The first start after a restore never looks anything up by itself.
- Haptics: only `N.tick()` (a light tick) on each step of the fuel gauge and the buffer / detour sliders. Loading: show the real tiles with a bar inside (`A.ldBar(label)`, or `progBar` in tripui, which follows `prog()`), never a blank area.
- Advisory → recall severity: `severity.js` rates each recall on the phone with all-MiniLM-L6-v2 (transformers.js, downloaded once from jsDelivr / Hugging Face; `MainActivity.aiFile` keeps the files in `files/ai`) by comparing it with example sentences per level; ratings are kept by recall number (`S.recallSev`). NHTSA's park-it / park-outside flags are serious without the model. Tests use `__mocks.severity`, never the download.
- Trip steps: Garage, Advisory (`advisory.js`: recalls, engine advice), Route, Parameters, Adjustments, Stops, Departure. Use the `ST_*` constants in `tripui.js`, never bare step numbers.
- `build.sh`: a Gradle-free build (aapt → javac → dx → zipalign → apksigner) that writes `Gasket.apk`.

## Commands
- All tests: `tests/run_all.sh [screenshot-dir] [test names…]`. It runs every Node test and every UI test once per phone size in parallel (`JOBS`, default: CPUs), about 1.5–2 minutes. Pass names to run only some, e.g. `tests/run_all.sh /tmp/shots trip_ui restore`. `NO_SCREENSHOTS=1` skips the PNGs for quick runs.
- The UI tests import `tests/fastwait.py`: `wait_for_timeout(ms)` returns once the page has settled (no timers, animation frames or CSS animations due within the window) instead of sleeping the full time. If a test looks timing-dependent, rerun it with `SLOW_WAITS=1`, and in new tests wait for the condition you mean (`wait_for_selector`, a flag) rather than a fixed time. `VIEWPORT_INDEX=0|1` runs one phone size.
- One Node test: `node tests/trip.test.js`. One UI test: `python3 tests/ui_test.py /tmp/shots`. The UI tests use the browser at `$CHROME`; the session-start hook sets it in cloud sessions.
- README screenshots: `python3 tools/readme-shots.py` (demo data) writes `docs/screenshots/`; the Garage and Stops shots are copied from the trip UI test (`pixel10pro-w1-garage`, `pixel10pro-t2-result`).
- Syntax check: `node --check assets/web/app.js`, `python3 -m py_compile tests/ui_test.py`. The `assets/*_worker.js` files are bare anonymous functions that the Java side wraps before injecting, so check those wrapped in parentheses.
- Build a signed APK: `./build.sh`. Cloud sessions sign with `KS_PASS` and `GASKET_KEYSTORE_B64` from the environment settings; elsewhere, set `KEYSTORE=/path/to.jks`. It fails if either is missing and never generates a key. See `SIGNING.md`. Never print, log or commit `KS_PASS`, `GASKET_KEYSTORE_B64` or the keystore, and don't dump the environment (`env`, `printenv`).

## Rules (from the owner; keep them)
- No user price reporting. If no source has a price, show the station without one.
- No CAPTCHA bypassing. Bot checks are completed by the user in a visible WebView.
- Never log, print, commit or export API keys or the keystore password. `log.js` scrubs keys and exports drop them.
- No horizontal scrolling anywhere. The UI tests check every step at 320–448 px and at 130% text size.
- Keep Google API use low: there's a monthly cap (default 900), answers are cached, and nothing searches automatically on open.
- No Play-services APIs. The target phones are Pixels on GrapheneOS.
- Test data uses generic public places (state capitols, "100 Main St", "Testville"), never real personal addresses, coordinates or share links.
- Keep compatibility: Restore full backup accepts Fuel+ 0.0.47 backups (`fromPackage` `com.ben.gasmap`, same `files/kv/<namespace>/<sha1>` layout); imports accept old Fuel+ exports (`fuelPlusData`) and old shared trips (`-----FUEL+ TRIP-----`).
- A restore, and the restart right after it, never use Google lookups; restored lookup counts keep the higher number.

## Working with the owner
- Small changes don't need the full test suite; run it on a larger batch of changes (it catches anything a small change broke). Still syntax-check what you touched.
- Changelog entries: the big things that matter, plus a general "Bug fixes" line instead of listing each fix.
- No popups (toasts) for things the screen already shows: missing fields get an outline or pulse, results show in place. Popups are only for errors and for save / backup / restore results.

## Versioning and commits
- `versionName` is always `0.0.<versionCode>` (see `VERSIONING.md`). Each bump gets a `CHANGELOG.md` entry.
- Use conventional commits (`feat:`, `fix:`, `chore:`, `test:`, `build:`, `docs:`, `refactor:`).
- `main` is the default branch. Pushing a new version to `main` releases it: the Release workflow tags it `v0.0.<code>` and publishes a source release (see `VERSIONING.md`); the signed build workflow adds a directly downloadable versioned APK after tests and signature verification. Don't push tags yourself or overwrite previously shipped APK assets.
- Licensed under the Source First License 1.1 (`LICENSE.md`). Third-party code keeps its own licenses (`THIRD_PARTY_NOTICES.md`). After editing either file run `node tools/gen-legal.js` (the app shows them from `assets/web/legal.js`; `tests/legal.test.js` fails when it's stale). A new bundled library or data source needs an entry there.
- Wherever Google Places/Routes content shows, add the "Google Maps" credit (`window.__app.gAttr()`). Open terms-of-service questions are in `COMPLIANCE.md`.
