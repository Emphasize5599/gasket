## Changes

- **Timezone availability:** a pinned, integrity-checked, unmodified 73,381-byte CC0 lookup resolves interior coordinates offline. Explicit facility zones and existing exact cached provider zones take priority. Nine probes across a roughly 3km neighborhood detect ambiguous boundaries and retain online resolution there; this is a compact estimate, not an exact global boundary database. IANA rules still handle DST. Offline estimates stay in memory instead of being persisted as exact provider answers. TrafficFlow and StopClock use the same fallback; repeated timezone validation uses a small valid-name set rather than constructing Intl formatters per cache hit. Package provenance, SHA-512 integrity and full license are bundled; vendor JS SHA-256 is `548133c31996a29b35120248e3ac92e4b7f50db5193a1c4a4da227e786b55c3a`.
- **Draft timing:** add/remove/time-selection update a small provisional clock with mapped previous fuel-stop positions, rest dwell, destination waits and EV destination charging. They do not collect station inventory, match station candidates or run Planner. A provisional clock is separate from `result`; it cannot become an approved fuel result. Earlier starts remain constrained to allowed windows and original later departures remain anchored. Actual final fuel/traffic timing is checked again before acceptance.
- **Fetch only needed roads:** entering a rest's timing first forecasts its approach, including earlier chosen rests/destination waits, and updates the provisional arrival. It does not forecast the remainder of the trip at provisional rest departures. The departure chart then forecasts the following leg. Existing road/time piece caches, observations and coalescing remain in use, so subsequent checks reuse valid data and fetch missing sections. A passed departure plus an impossible rest closing time is explained before unnecessary traffic work.
- **Final fuel work:** Finish rest timing yields for the UI to paint, then runs price preflight and the actual fuel optimizer against remembered stations. A genuine coverage-related failure invokes station discovery/recovery before rejection. Timing-window violations do not launch station discovery. The original starting fuel is preserved; fuel/charging dwell, rates, reserve, windows, original departure anchors and changed hazards still gate final acceptance.
- **Foreground priority:** a balanced foreground scope pauses queued background access work and automatic recommendation validity while approach/departure/final traffic is needed. Existing short active reads can finish. All paused passes resume, including after cancellation/errors; normal shared provider pacing remains intact. Broad directory redraws pause during foreground sampling.
- **Remaining CPU work:** candidate matching yields after about 8ms of work instead of a fixed 25 stations. Projection memo capacity increases from 4,096 to 16,384, preventing repeated full scans when a saved inventory has 8,028 unique locations. Existing route geometry results are reused without changing matching precision. Initial rest seeds use the current saved/previous inventory; recovery queries shared geographic inventory if more is needed.
- **Storage and errors:** draft saves coalesce for 750ms, preserve original station lists and do not recollect them. Saved route state includes `restEditing` and the earlier-start restoration metadata. Unavailable departure forecasts remain gray/unverified, show a retry action, and produce a warning summary with available/unavailable/window-blocked counts and distinct failure reasons. Review-slider failures appear inline rather than as unhandled rejected promises.
