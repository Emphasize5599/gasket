## Actual detail/search probes

### FreeCampsites

The generic web-fetch tool returned 502 for the home page; the actual desktop browser loaded it and completed a signed-out `Wall, South Dakota` search. Therefore that fetch failure was not proof the site was down.

The browser's own resource inventory exposed an area-search request to `wp-content/themes/freecampsites/androidApp.php` with location/coordinates/advancedSearch parameters and a detail request with `siteid=20573`. A direct HTTP detail request succeeded 200 with **647,443 bytes of valid JSON**, about **613 ms** on one desktop repeat. It was served as `text/html`, so displaying it in a browser parsed embedded HTML into the DOM and made `body.innerText` unsuitable as a JSON source. Parse the actual HTTP body; don't invent a repair from altered DOM text.

The detail object included ID, coordinates, original listing date, update timestamp, category, a price field, image references, ratings, access-specific data and comments. Its price field was empty even though the website presented it as free: the category/type-specific schema still needs verification before mapping to a numeric zero. One detail response included 159 comments and 20 image entries, so don't load all detailed responses along an entire route by default. Search summaries first; fetch selected candidates on demand; open the original site for the full gallery/reviews. No undocumented field-projection or lightweight endpoint was verified.

An independent HTTP area-search request failed JSON parsing. The working browser search does not prove a standalone, complete or stable area API. A future reader should measure cold/warm browser requirements, paging/limits, explicit restriction/error handling and deduplication before adoption. No private token or sign-in was used for the successful detail request.

### OpenCampingMap

Selected [Buffalo Gap National Grassland](https://opencampingmap.org/en/way/1299398879) from the actual map. Its panel exposed OSM-backed vehicle/access/fee/amenity facts and an external review service. This verifies a public detail-link experience; it does not validate OSM's US inventory completeness or identify real-time space availability. Obtain licensed OSM records directly, rather than scraping this rendering service to reconstruct OSM.

### Cross-source freshness and identity example

[Campendium's Nomad View page](https://maps.campendium.com/us/wall-sd/places/nomad-view-dispersed-camping) and [FreeCampsites' Badlands Overlook page](https://freecampsites.net/#!20573&query=sitedetails) describe the same general camping area under different names. FreeCampsites showed a 2020 description date with 2026 reports/update activity. Current reports described changes to where camping is allowed. This is why description age, report dates and fetched-at time must remain separate.

Nearby OSM polygons/pins can represent a larger camping area, a particular entrance or another subarea. Do not auto-merge solely because names are similar or coordinates are nearby. Preserve external IDs, geometry role, entrance/access route and linked source records. Prefer the managing agency for rules/closures; retain disagreement in visitor reports without declaring one amenity answer verified.

## Recommended first implementation

1. **Own a persistent inventory from government and OSM sources.** Keep short rest parking, permitted overnight vehicle parking, drive-in camping and hike-in camping distinct. Exclude hike-in access from ordinary roadside suggestions. Store actual access/vehicle restrictions, free/paid/unknown status, permit/reservation requirements, stay limits and source timestamps.
2. **Use external detail pages to let the user inspect a stop.** Start with exact FreeCampsites and Campendium links where matched, alongside the agency page and an OSM/OpenCampingMap link. An external listing link is useful independently of permission to copy/rehost its gallery, reviews or database. Do not insert a campground's individual tent-pitch link as if it were its road entrance.
3. **Prioritize a limited FreeCampsites reader experiment.** A public structured detail response is proven; full search/coverage and storage/reuse remain unverified. Keep this opt-in research until those are settled. Human-readable evidence and dates must survive extraction. Do not turn a blank price into $0.
4. **Use verified filter handoff.** RV Parky category/amenity/radius URLs and selected Campendium filters survived reload. FreeCampsites needs page-control application or Gasket-filtered detail links because its ordinary location URL omitted advanced filters. See [CAMPSITE_FILTERS.md](CAMPSITE_FILTERS.md). iOverlander is excluded at the owner's request (RETIRED_WORK.md); Dyrt remains optional. No account or outreach was performed.
5. **Rank for the actual purpose.** A remote scenic campsite may suit an overnight stay but be a poor 20-minute traffic break. Include routed detour, surface/ground clearance/trailer suitability, access hours, weather, remaining range and expected stay. Show unknowns and alternative stops; a historical free listing is not present-day permission or a guarantee of space.

Suggested concise controls: `Rest stop`, `Overnight parking`, `Campground`; `Free only` / `Allow paid`; and `View photos & recent reports` opening the source website. No new UI was implemented in this research pass.
